# hello-004

A monorepo with a Go API and a SvelteKit app, sharing types generated from Go. pnpm workspaces and Turborepo at the centre; development inside containers.

## Structure

```
apps/
  api/              Go API (chi + huma)
  web/              SvelteKit app, with its Storybook
packages/
  types/            Go structs, with their TS types generated by tygo
  shared/           Hand-written TS shared by the frontend packages (Zod schemas, helpers)
e2e/
  web/              End-to-end tests of web (Playwright)
scripts/            Maintenance scripts (versions, Go sync)
tools/              Go dev tools (wgo, Delve, tygo): a module with no code, outside go.work
docs/guide.md       The rules this project follows
```

## Prerequisites

- Docker with Compose. Nothing else: Node, pnpm and Go live in the images, and development happens inside the containers.
- VS Code, attached to the running editing container (`./code-attach.sh`, which needs `code` on the host).
- Files created by the containers belong to user id 1000 on the host. On Linux, work as that user.

Only want to try it, without Docker? See [Quick run without Docker](#quick-run-without-docker).

## Getting started

A fresh clone first needs each app's secrets file (gitignored), from its committed example:

```bash
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
```

Both hold `API_SECRET`, which must be the same in both; replace `change-me` with a random value (`head -c 32 /dev/urandom | base64`) if the stack is reachable by anyone else. Then:

```bash
docker compose up -d
```

This builds the images and starts every service. The first start installs everything and takes a few minutes.

- web: http://localhost:5180
- web's Storybook: http://localhost:6006
- api: http://localhost:8090/healthz (every other route needs the `X-Api-Secret` header)

### Services

| Service         | Image             | What it does                                                                                                                    |
| --------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `editing`       | `all.Dockerfile`  | Runs nothing. The editor attaches here; git, the hooks, checks, tests and builds run here                                       |
| `maintenance`   | `all.Dockerfile`  | Installs dependencies, builds the Go tools, downloads the test browser, generates the TS types, then regenerates them on change |
| `api`           | `go.Dockerfile`   | The Go API on port 8090, rebuilt and restarted on change                                                                        |
| `web`           | `node.Dockerfile` | The SvelteKit dev server on port 5180                                                                                           |
| `web-storybook` | `node.Dockerfile` | web's Storybook on port 6006                                                                                                    |

The app services wait for `maintenance` to be healthy. The whole repo is bind-mounted into every container at `/monorepo`. Compose starts each program directly (`vite`, `storybook`, `wgo`), with no `pnpm run` in between; Turborepo runs the tasks (checks, tests, builds, code generation), not the apps.

### Lean and full mode

```bash
docker compose up -d                                          # lean: apps only
docker compose -f compose.yaml -f compose.full.yaml up -d     # full: apps with their debuggers on
```

In full mode the JS app listens for a debugger on port 9229 and the Go app on 2345, inside the Compose network only. Attach from the editor (attached to `editing`) with the "(Docker)" configuration in each app's `.vscode/launch.json`.

### Working in the repo

Attach the editor (`./code-attach.sh`, or `./code-attach.sh apps/web` for one folder), then in its terminal:

```bash
pnpm turbo run lint:check format:check typecheck   # what the pre-push hook runs
pnpm turbo run test:unit                           # unit and story tests
pnpm turbo run test:e2e                            # end-to-end, against the running stack
pnpm turbo run build --filter web
```

Commits are made in the editing service, where the hooks run: pre-commit fixes the staged files, pre-push checks (no tests: those are for CI).

### Changing how an app starts

Each app's start command is written twice: in `compose.yaml` (its full-mode version in `compose.full.yaml`), and as the app's `dev:lean` / `dev:full` scripts, which the host run uses. Each Storybook's command likewise, as its package's `storybook:dev`. **When you change one, change the other in the same commit.** The only intended difference: in the full-mode scripts the debuggers listen on `127.0.0.1`, the JS ones on a random port.

### Env vars and secrets

Compose injects every variable. Non-secret values are in `compose.yaml`; secrets in each app's gitignored `.env`, listed with dummy values in its committed `.env.example`. There is no root `.env`.

### Go dev tools

wgo, Delve and tygo are listed in `tools/go.mod`, a module with no code, kept out of `go.work` so the tools' dependencies never change the apps' versions. `maintenance` installs them into `$GOPATH/bin`, and everything calls them by name. Every command in `tools/` needs `GOWORK=off`.

### Go modules in sync

Inside `go.work`, Go builds every module with the highest version any module asks for; a module built on its own (a production image) uses only its own `go.mod`. `./scripts/check-go-sync.sh` reports any module that would build differently on its own, with the fix (`go work sync`, then `GOWORK=off go mod tidy` in each module it names). It changes nothing, and runs in the pre-push hook.

### Tool versions

Every toolchain version (Node, pnpm, Go, the Go linter, the images' Debian release, and the Playwright that picks the test browser's system libraries) is written once, in the build arguments at the top of `compose.yaml`. Change one there by hand, rebuild (`docker compose up -d --build`), then run the matching script inside `editing`:

| Script                             | What it does                                                                                  |
| ---------------------------------- | --------------------------------------------------------------------------------------------- |
| `./scripts/check-versions.sh`      | Changes nothing. Reports everything out of step with `compose.yaml` and which script fixes it |
| `./scripts/update-go-version.sh`   | Sets the `go` line of `go.work` and every `go.mod`                                            |
| `./scripts/update-pnpm-version.sh` | Sets the pnpm range in the root `package.json` to a new major; then restart `maintenance`     |
| `./scripts/update-node-types.sh`   | Moves `@types/node` to Node's major, as an exact version                                      |

## Quick run without Docker

For a quick look only, not for development. You need Node, pnpm and Go installed; their versions are not checked (the containers' are at the top of `compose.yaml`).

```bash
pnpm install
(cd tools && GOWORK=off go install tool)    # the Go dev tools
export PATH="$PATH:$(go env GOPATH)/bin"    # if Go's bin folder isn't on your PATH yet
cp apps/api/.env.example apps/api/.env; cp apps/web/.env.example apps/web/.env
set -a; . apps/api/.env; set +a          # API_SECRET, for both apps
export PORT=8090 API_URL=http://localhost:8090
pnpm dev:lean     # or: pnpm dev:full, with the debuggers on
```

One command generates the TS types (and regenerates them on change), then starts both apps. A Storybook runs on its own: `pnpm turbo run storybook:dev --filter web`. In full mode the debuggers listen on `127.0.0.1` only; attach with the "(host)" configurations.

Don't switch between this and the containers in the same clone: both use the same `node_modules`, and each side reinstalls it for itself.
